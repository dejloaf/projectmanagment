

# Фаза 3: Оценка проекта

В качестве объекта оценки рассматривается проект **SmartExpense — мобильное приложение для учёта личных расходов**, выбранный в фазе 1.

---

## Use Cases проекта

Для проекта были сформированы следующие пользовательские сценарии (Use Cases), включая альтернативные и негативные:

1. Регистрация пользователя
2. Авторизация пользователя
3. Добавление нового расхода
4. Редактирование расхода
5. Удаление расхода
6. Просмотр списка расходов
7. Фильтрация и поиск расходов
8. Просмотр статистики и диаграмм
9. Управление категориями расходов
10. Экспорт данных (CSV / PDF)
11. Восстановление доступа (негативный сценарий)
12. Обработка ошибки ввода данных (негативный сценарий)
13. Анализ спонтанных трат

Всего: **12 Use Cases**.

---

## Оценка в COSMIC Function Points

Проект был оценён методом **COSMIC Function Points** на основе анализа функциональных пользовательских процессов.

Для основных Use Cases были выделены следующие типы функциональных процессов:

* Entry (E),
* Exit (X),
* Read (R),
* Write (W).

Суммарная оценка проекта составила:

* **COSMIC FP ≈ 43**

Данная величина соответствует проекту среднего масштаба с преобладанием CRUD-операций и элементами аналитики.

---

## Оценка в Use Case Points (UCP)

Use Cases были классифицированы по сложности:

* Простые — 5
* Средние — 5
* Сложные — 2

Actor’ы:

* Простой актор (мобильный пользователь) — 1
* Админ
* Система уведомлений

На основе стандартной методики Use Case Points с учётом:

* Unadjusted Use Case Weight (UUCW),
* Unadjusted Actor Weight (UAW),
* технических и средовых коэффициентов,

получено:

* **UCP ≈ 104**

При использовании усреднённого коэффициента продуктивности
**20 человеко-часов / UCP**, трудоёмкость оценивается как:

* **≈ 2080 человеко-часов**

---

## Оценка трудозатрат по Use Cases

Use Cases были дополнительно оценены в относительных единицах (story points) по методу экспертной договорённости:

* Простые Use Cases — 8 SP
* Средние Use Cases — 13 SP
* Сложные Use Cases — 21 SP

Суммарная оценка проекта:

* **≈ 120 story points**

---

## Агрегация оценок и выводы

Сравнение различных методов оценки показывает сопоставимые результаты, что подтверждает устойчивость полученных выводов.

На основе агрегированных оценок можно сделать следующие выводы:

* проект относится к **среднему масштабу**;
* оптимальный размер команды — **3–4 человека**;
* рекомендуемый состав команды:

  * 2 backend / mobile разработчика,
  * 1 frontend / UI разработчик,
  * 1 тестировщик (неполная занятость);
* ориентировочный срок реализации MVP — **2,5–3 месяца**.

---

## Возможности сокращения объёма проекта

В случае необходимости сокращения сроков разработки без потери базовой функциональности могут быть исключены или отложены:

* экспорт данных;
* расширенные визуализации статистики;
* гибкая настройка категорий.

Эти функции вносят заметный вклад в трудоёмкость проекта, но не являются критичными для базового сценария использования.
